# Evidence bundle wire specification — `0.2`

**Status:** pre-alpha. This document specifies the canonical wire form, hash
projection and verification procedure of the Ariadne evidence bundle with
`schema_version` `0.2`. It is a faithful restatement of the ratified decision
records [ADR-0006](../../adr/ADR-0006-evidence-bundle-wire-contract.md),
[ADR-0010](../../adr/ADR-0010-provenance-scope-and-digest-class.md),
[ADR-0012](../../adr/ADR-0012-evidence-bundle-integration-precisions.md) and
[ADR-0016](../../adr/ADR-0016-wire-versioning-and-product-vocabulary.md), which
remain normative. If this document and the decision records disagree, the
records win.

The key words **MUST**, **MUST NOT**, **SHALL** and **MAY** are to be
interpreted as described in RFC 2119.

This specification is publishable without authorizing distribution: shipping
bundles to consumers remains a separate, owner-gated decision. Ariadne is
pre-alpha and nothing here claims deployment compatibility, authenticity of any
source, or fitness for production.

## 1. The three artifacts

An evidence bundle is delivered as three artifacts:

| Artifact | Content |
|---|---|
| `bundle.json` | The complete canonical envelope: subject, images, evidence, and run provenance. |
| `bundle.hash-input.json` | The exact bytes of the hash projection: the provenance claims without operational metadata. |
| `bundle.sha256` | One line, `sha256:<64 lowercase hex>` plus a trailing `LF` (`0x0A`): the SHA-256 digest of the hash projection bytes. |

The digest proves **integrity of the hash projection bytes**. It does not prove
authenticity of the origin, of the cluster described, or of any file it
references. It is never embedded inside `bundle.json`.

## 2. Encoding rules (canonical serialization)

Every JSON document on this wire — the envelope and the hash projection —
**MUST** be serialized as follows:

1. UTF-8, without a BOM.
2. A single JSON value on one line: no whitespace outside tokens, no trailing
   newline at the end of the document.
3. No HTML escaping: the characters `<`, `>` and `&` appear literally inside
   strings.
4. String escaping (all other valid UTF-8 is emitted as-is, never as `\uXXXX`):

   | Code point | Serialized as |
   |---|---|
   | `"` | `\"` |
   | `\` | `\\` |
   | `U+0008` (backspace) | `\b` |
   | `U+000C` (form feed) | `\f` |
   | `U+000A` | `\n` |
   | `U+000D` | `\r` |
   | `U+0009` | `\t` |
   | other code points below `U+0020` | `\u00xx`, lowercase hex |
   | `U+2028` | `\u2028` |
   | `U+2029` | `\u2029` |

5. Numbers are unsigned integers in plain decimal notation: no exponent, no
   leading zeros, no `+` sign, no fraction.
6. Object keys appear in the fixed orders defined in §3 and §8. A conforming
   producer **MUST NOT** emit any other key order, and a key not defined in
   this specification **MUST NOT** appear.
7. An absent optional value is `null`, never an omitted key and never `""`.
8. Input strings **MUST** be valid UTF-8 before serialization; identifiers and
   paths additionally **MUST NOT** be empty or carry surrounding whitespace.
   Free-text fields (warning messages, error strings) **MUST** be non-empty
   after trimming but keep their internal whitespace, because the bytes are
   hashed as written.

## 3. Envelope structure and key order

`bundle.json` is one JSON object with exactly these members, in this order:

| # | Key | Content |
|---|---|---|
| 1 | `schema_version` | String, always `"0.2"` for a producer of this specification (§5). |
| 2 | `subject` | Object, §3.1. |
| 3 | `images` | Array of objects, §3.2. Array, never `null`; MAY be empty. |
| 4 | `evidence` | Array of objects, §3.3. Array, never `null`; MAY be empty. |
| 5 | `observed_container_classes` | Array of strings, never `null`; MAY be empty. |
| 6 | `provenance` | Object, §3.4. |

### 3.1 `subject`

| # | Key | JSON type | Rules |
|---|---|---|---|
| 1 | `cluster_alias` | string | Non-empty, no surrounding whitespace. A non-secret alias, never a URL with credentials. |
| 2 | `namespace` | string | Non-empty, no surrounding whitespace. |
| 3 | `kind` | string | Non-empty, no surrounding whitespace (e.g. `"Pod"`). |
| 4 | `name` | string | Non-empty, no surrounding whitespace. |
| 5 | `uid` | string | Non-empty. The workload identity; `namespace`/`name` is **not** identity. |
| 6 | `owner_chain` | string or `null` | `null` when not observed. |

### 3.2 `images[]`

| # | Key | JSON type | Rules |
|---|---|---|---|
| 1 | `container_class` | string | One of `regular`, `init`, `ephemeral` (§4). |
| 2 | `container_name` | string | Non-empty, no surrounding whitespace. |
| 3 | `requested_image` | string or `null` | The image as requested (declared), verbatim. |
| 4 | `raw_image_id` | string or `null` | The observed image reference as seen. |
| 5 | `normalized_digest` | string or `null` | A digest the producing parser guarantees to be unambiguous. |
| 6 | `platform` | object | §3.2.1. |
| 7 | `observed_at` | string or `null` | Timestamp (§4.2). |

A declared or observed value that is present **MUST** be non-empty. A mutable
tag is never evidence of content: `requested_image` and `normalized_digest` are
separate claims. An index digest and a platform manifest digest are not
interchangeable; a digest whose class the source does not prove stays only in
`raw_image_id` with platform `unknown`.

#### 3.2.1 `platform`

| # | Key | JSON type | Rules |
|---|---|---|---|
| 1 | `os` | string or `null` | `null` unless `status` is `known`. |
| 2 | `architecture` | string or `null` | `null` unless `status` is `known`. |
| 3 | `status` | string | `known` or `unknown` (§4). |

When `status` is `known`, `os` and `architecture` **MUST** be non-empty
strings and `normalized_digest` **MUST** be present. When `status` is
`unknown`, `os` and `architecture` **MUST** be `null`. The platform is never
inferred from the host, the build or the process.

### 3.3 `evidence[]`

| # | Key | JSON type | Rules |
|---|---|---|---|
| 1 | `type` | string | Non-empty, no surrounding whitespace. The evidence type name (§4.3). |
| 2 | `source` | string | Non-empty, no surrounding whitespace. |
| 3 | `source_hash` | string | Non-empty. Hash of the referenced source, as produced by the caller. |
| 4 | `locator` | string | Non-empty. Position of the fact inside the source. |
| 5 | `value` | string or `null` | The fact itself, bounded and sanitized. |
| 6 | `value_hash` | string or `null` | Non-empty when present, without surrounding whitespace. Transport validation and producer preimage: §4.4. |
| 7 | `observed_at` | string | **Required**, never `null`. Timestamp (§4.2). |
| 8 | `confidence` | string | One of `observed`, `derived`, `unavailable` (§4). |
| 9 | `scope` | object | §3.3.1. |
| 10 | `warnings` | array of warning objects | Never `null`; MAY be empty. Warning object: §3.5. |

`value` present requires `value_hash` present. An item MAY carry only
`value_hash` (with `value` = `null`) when the value is not carried verbatim;
the hash then still allows auditing. `confidence: "unavailable"` records that
the fact was not obtained or is out of scope — it is not a negative result.

#### 3.3.1 `scope`

| # | Key | JSON type | Rules |
|---|---|---|---|
| 1 | `subject_uid` | string | Non-empty; **MUST** equal `subject.uid`. |
| 2 | `container_name` | string | Non-empty. |

Every evidence item is scoped to one subject and one container. Mixing
evidence between subjects is a contract violation, not a formatting detail.

### 3.4 `provenance`

| # | Key | JSON type | Rules |
|---|---|---|---|
| 1 | `collector_version` | string | Non-empty. |
| 2 | `parser_version` | string | Non-empty. |
| 3 | `ruleset` | object or `null` | §3.4.1. |
| 4 | `argv_sanitized` | array of strings | Never `null`; MAY be empty. Sanitized command line. |
| 5 | `inputs` | array of objects | Never `null`; MAY be empty. Input object: §3.4.2. |
| 6 | `api_scope` | object | §3.4.3. |
| 7 | `started_at` | string or `null` | Timestamp (§4.2). |
| 8 | `ended_at` | string or `null` | Timestamp (§4.2). Not before `started_at`. |
| 9 | `budget` | object | §3.4.4. |
| 10 | `coverage` | object | §3.4.5. |
| 11 | `completeness` | string | `complete`, `partial` or `unknown` (§4). |
| 12 | `consistency` | string | `point-observation` or `not-atomic` (§4). |
| 13 | `redaction_policy` | string | Non-empty. |
| 14 | `warnings` | array of warning objects | Never `null`; MAY be empty. |
| 15 | `errors` | array of strings | Never `null`; MAY be empty. Sanitized messages. |

When `completeness` is not `complete`, `errors` **MUST** be non-empty: an
incomplete run reports visibly, never silently. If `started_at` and `ended_at`
are both present, `started_at` **MUST NOT** be after `ended_at`.

#### 3.4.1 `ruleset` (when not `null`)

| # | Key | JSON type | Rules |
|---|---|---|---|
| 1 | `path` | string | Non-empty. |
| 2 | `hash` | string | Non-empty. |
| 3 | `version` | string | Non-empty. |

#### 3.4.2 `inputs[]`

| # | Key | JSON type | Rules |
|---|---|---|---|
| 1 | `path` | string | Non-empty, no surrounding whitespace. |
| 2 | `hash` | string | Non-empty. |

#### 3.4.3 `api_scope`

| # | Key | JSON type | Rules |
|---|---|---|---|
| 1 | `namespaces` | array of strings | Never `null`; MAY be empty. Each entry non-empty. |
| 2 | `verbs` | array of strings | Never `null`; MAY be empty. Each entry non-empty. |
| 3 | `resources` | array of strings | Never `null`; MAY be empty. Each entry non-empty. |

#### 3.4.4 `budget`

| # | Key | JSON type | Rules |
|---|---|---|---|
| 1 | `wall_clock` | string | Valid UTF-8; MAY be empty. |
| 2 | `requests` | number | Unsigned integer. |
| 3 | `objects` | number | Unsigned integer. |
| 4 | `bytes` | number | Unsigned integer. |

#### 3.4.5 `coverage`

| # | Key | JSON type | Rules |
|---|---|---|---|
| 1 | `method` | string | `findings_import` or `container_observation` (§4). |
| 2 | `termination` | string | `finished`, `aborted` or `unknown` (§4). |
| 3 | `rows` | object or `null` | §3.4.6. |

#### 3.4.6 `coverage.rows` (findings import only)

| # | Key | JSON type | Rules |
|---|---|---|---|
| 1 | `total` | number or `null` | `null` while the file extent is unknown. |
| 2 | `accepted` | number | Unsigned integer. |
| 3 | `rejected` | number | Unsigned integer. |

### 3.5 Warning object

Warnings are typed objects, never free strings:

| # | Key | JSON type | Rules |
|---|---|---|---|
| 1 | `code` | string | Non-empty. §4.5 defines the codes this version interprets. |
| 2 | `class` | string | `informational` or `contradictory` (§4). |
| 3 | `message` | string | Non-empty after trimming; internal whitespace preserved. |

A reader that meets a `code` outside §4.5 keeps the warning and treats it as
uninterpretable; an unknown code or a `contradictory` warning cannot support a
favourable conclusion.

## 4. Vocabularies and value rules

### 4.1 Enumerations

| Field | Allowed values |
|---|---|
| `images[].container_class`, `observed_container_classes[]` | `regular`, `init`, `ephemeral` |
| `images[].platform.status` | `known`, `unknown` |
| `evidence[].confidence` | `observed`, `derived`, `unavailable` |
| warning `class` | `informational`, `contradictory` |
| `provenance.completeness` | `complete`, `partial`, `unknown` |
| `provenance.consistency` | `point-observation`, `not-atomic` |
| `provenance.coverage.method` | `findings_import`, `container_observation` |
| `provenance.coverage.termination` | `finished`, `aborted`, `unknown` |

### 4.2 Timestamps

Timestamps are instants in UTC. The producer **MUST** convert to UTC before
emission; the serialized form is RFC 3339 with the `Z` offset (for example
`2026-09-23T12:00:00Z`). Fractional seconds appear only when the instant
carries them. No timestamp is generated during serialization.

### 4.3 Evidence type names

`evidence[].type` is an open string at the transport layer: this wire does not
impose a universal allowlist. Version `0.2` adds the reserved `product_v1.*`
vocabulary below. Import-produced items use names such as
`prisma_v1.<column>` (declared values) and `container_status.*` (observed
values); those names are established by the producing adapters, not by this
specification.

### 4.4 `value_hash`: transport validation and producer preimage

At the transport layer, a present `value_hash` is a non-empty UTF-8 string
without surrounding whitespace. A present `value` requires a present
`value_hash`; a hash-only item remains permitted. Structural validation does
not enforce a digest algorithm or length and does not recompute the hash.

For evidence items produced by the import mapping in ADR-0012, the producer
computes `value_hash` as `sha256:` followed by 64 lowercase hex characters of
the SHA-256 digest over the exact UTF-8 bytes of the value string, with no
JSON quoting, trimming or normalization. When the value is not carried
verbatim, the producer hashes the original value bytes. This producer rule
does not strengthen transport validation.

`CanonicalJSON` and `Encode` do not establish the correctness of individual
value hashes. `Encode` cross-checks the bundle's hash projection. Evaluation
performs separate integrity checks for present values of recognized evidence
types according to the selected profile; transport acceptance alone does
not establish that evidence can support an evaluation.

### 4.5 Warning codes known in `0.2`

`uid_changed`, `scope_mismatch`, `partial_observation`, `stale_observation`,
`source_conflict`, `redaction_applied`, `tool_failure`.

### 4.6 The `0.2` product vocabulary

Version `0.2` introduces the exact evidence type names below. The grammar is
`product_v1.<family>.<field>`, where `<family>` is exactly `mapping`,
`artifact` or `vendor`, and `<field>` matches `[a-z][a-z0-9_]{0,31}` (lowercase
ASCII, 1–32 bytes, starting with a letter). A full name is ASCII and at most 52
bytes. There is no wildcard: a name exists only if it is listed, and no prefix
match, longer name or variant spelling extends the catalogue.

| Prefix | Exact suffixes |
|---|---|
| `product_v1.mapping.` (14) | `method`, `coverage`, `vulnerability_id`, `scanner_package_type`, `scanner_package_name`, `scanner_package_id`, `vendor`, `product_id`, `product_release`, `os`, `architecture`, `component_id`, `package_name`, `package_arch` |
| `product_v1.artifact.` (15) | `method`, `coverage`, `artifact_digest`, `digest_kind`, `vendor`, `product_id`, `product_release`, `os`, `architecture`, `component_id`, `package_name`, `package_arch`, `epoch`, `version`, `package_release` |
| `product_v1.vendor.` common (21) | `method`, `coverage`, `vulnerability_id`, `advisory_id`, `advisory_revision`, `vendor`, `product_id`, `product_release`, `os`, `architecture`, `component_id`, `package_name`, `package_arch`, `epoch`, `version`, `package_release`, `source_status_vocabulary`, `source_status_value`, `proof_kind`, `basis_id`, `basis_locator` |
| `product_v1.vendor.` additions for `vulnerable_build` (2) | `vulnerable_code_id`, `applicability` |
| `product_v1.vendor.` additions for `fixed_build` (3) | `fixed_code_id`, `fix_id`, `fix_membership` |
| `product_v1.vendor.` additions for `code_excluded_build` (4) | `excluded_code_id`, `build_id`, `exclusion`, `exclusion_coverage` |

`product_v1.artifact.digest_kind` with value `platform_manifest` is a scalar
digest-class claim with per-item provenance. It is not a new JSON member, does
not fill or change `normalized_digest`, and an index digest or an ambiguous
class does not satisfy it. The joining, validity and evaluation requirements of
these records belong to a separate domain contract; transport acceptance alone
grants no affirmative authority.

## 5. Schema versioning

`schema_version` has the grammar `MAJOR.MINOR`: two decimal numbers, no leading
zeros. A reader of this contract **MUST** accept `0.0`, `0.1` and `0.2` and
**MUST** reject any other major and any minor newer than `2`, fail-closed:
there is no downgrade and no automatic migration. A producer of this
specification **MUST** emit `0.2` on every bundle, including ordinary imports
with no `product_v1.*` evidence. Version incompatibility is never a technical
`not_affected` result.

Historical bundles stay verifiable under their original version. Rebuilding
evidence produces a new bundle, not a revision of the old artifact.

## 6. Canonical collection order

Before serialization the producer **MUST** order the contractual collections
as follows. Comparisons are lexicographic over UTF-8 bytes; sorts are stable;
`null` orders before any present value when a nullable field is part of a sort
key. A `null` collection stays `null` in validation terms and an empty
collection stays empty — ordering never collapses one into the other.

| Collection | Sort key, in order |
|---|---|
| `images[]` | `container_class`, `container_name`, `requested_image`, `raw_image_id`, `normalized_digest`, `platform.os` (null unless `known`), `platform.architecture` (null unless `known`), `platform.status`, `observed_at` (chronological, `null` first) |
| `evidence[]` | `scope.subject_uid`, `scope.container_name`, `type`, `source`, `locator`, `source_hash`, `observed_at` (chronological, `null` first), `value_hash` (`null` first), `confidence`, `value` (`null` first), `warnings` (list order, §3.5 keys) |
| `evidence[].warnings[]`, `provenance.warnings[]` | `code`, `class`, `message` |
| `provenance.errors[]` | the UTF-8 bytes of each string's canonical JSON encoding (quotes and escapes included) |
| `provenance.inputs[]` | `path`, `hash` |
| `provenance.api_scope.namespaces[]`, `.verbs[]`, `.resources[]` | the string itself |
| `observed_container_classes[]` | the string itself |

## 7. Validation rules (bundle-level cross-checks)

Beyond the field rules of §3, a conforming bundle **MUST** satisfy:

1. `observed_container_classes` **MUST NOT** contain duplicates.
2. Every `evidence[].scope.subject_uid` **MUST** equal `subject.uid`.
3. `coverage.method` = `findings_import` requires: exactly one entry in
   `provenance.inputs`; empty `api_scope.namespaces`, `.verbs` and
   `.resources`; empty `observed_container_classes`; `coverage.rows` present.
4. `coverage.method` = `container_observation` requires `coverage.rows` =
   `null`, and every `images[].container_class` **MUST** appear in
   `observed_container_classes`.
5. `coverage.termination` = `unknown` requires `completeness` = `unknown`.
6. `completeness` = `complete` requires: `coverage.termination` = `finished`;
   empty `provenance.errors`; for a findings import, `rows.total` known and
   `rows.accepted` = `rows.total` with `rows.rejected` = 0; for a container
   observation, all three classes (`regular`, `init`, `ephemeral`) observed.
7. `coverage.termination` = `aborted` requires `completeness` = `partial` when
   progress is verifiable (rows counted or extent known; classes observed or
   images inventoried) and `completeness` = `unknown` otherwise.
8. `rows.accepted` + `rows.rejected` **MUST NOT** overflow unsigned 64-bit and
   **MUST NOT** exceed `rows.total` when `total` is known; a finished import
   requires a known total and `accepted` + `rejected` = `total`.
9. `completeness` ≠ `complete` requires `provenance.errors` non-empty (rule
   restated from §3.4).

## 8. Hash projection

The hash input is derived from the canonical envelope:

1. Start from the canonical `bundle.json` bytes (§2–§6). The projection keeps
   the canonical order of every array as it appears in the envelope; it never
   re-sorts or re-encodes strings.
2. Keep the six top-level members in their order, with their exact bytes:
   `schema_version`, `subject`, `images`, `evidence`,
   `observed_container_classes`, `provenance`.
3. In `provenance`, keep exactly nine members in this order: `ruleset`,
   `inputs`, `api_scope`, `coverage`, `completeness`, `consistency`,
   `redaction_policy`, `warnings`, `errors`.
4. **Exclude** the operational metadata: `collector_version`, `parser_version`,
   `argv_sanitized`, `started_at`, `ended_at`, `budget`, and `ruleset.version`.
5. Reduce `ruleset` to `{"path":…,"hash":…}` in that order; a `null` ruleset
   stays `null`.
6. Serialize the projection with the rules of §2.

The digest is SHA-256 over those exact projection bytes, rendered as
`sha256:` plus 64 lowercase hex characters. Consequences: changing
`ruleset.version`, `argv_sanitized`, `budget`, run timestamps or the
collector/parser versions changes `bundle.json` but **not** the digest;
changing anything else does.

## 9. Third-party recalculation procedure

Given the three published files, a verifier with any conforming JSON tool can
reproduce the digest without Ariadne:

1. Read `bundle.json` as UTF-8. Confirm: no BOM, exactly one line, no trailing
   newline, no `<`/`>`/`&` escapes, and the key orders of §3.
2. Confirm `schema_version` is `0.2` and passes §5.
3. Build the projection: copy the six top-level members byte-for-byte (§8
   step 2), rebuild `provenance` with the nine members of §8 step 3, reduce
   `ruleset` per §8 step 5, and drop the members of §8 step 4.
4. Serialize the projection with the rules of §2 and compare the bytes with
   `bundle.hash-input.json`. They **MUST** be identical.
5. Compute SHA-256 over those bytes. The result as `sha256:` plus lowercase
   hex **MUST** equal the content of `bundle.sha256` (ignoring the trailing
   `LF` of that file).
6. Optional sanity checks: for items with a present string value and a known
   producer preimage rule, recompute `value_hash` using that rule (§4.4).
   A hash-only item's preimage cannot be checked from the bundle alone.
   Re-derive the canonical order of §6 from an unordered copy of the envelope.

## 10. Published vectors

The directory `0.2/` next to this document contains one synthetic vector:

| File | Bytes |
|---|---|
| `0.2/bundle.json` | 2973 |
| `0.2/bundle.hash-input.json` | 2681 |
| `0.2/bundle.sha256` | 72 (digest line + `LF`) |

Digest of the vector: `sha256:84bfab22e74237ab559a54598ea11b22e3416088d54a0a7657fdb726151fcf6a`.

All data in the vector — namespaces, names, UIDs, image references, advisory
identifiers and source hashes — is synthetic. The `source_hash` values refer to
sources that are not shipped; they are well-formed constants, not digests of
published files. The vector exercises: a findings import with complete
coverage; one image with known platform and normalized digest; an observed
`container_status.image_id` item; two `product_v1.*` items, one with `value`
present and one hash-only (`value` = `null`); a `ruleset`; a provenance
warning; and the empty-array forms of the import case.

The vector was produced by the repository's own encoder
(`internal/bundle.Encode`), which additionally cross-checks that the projection
rebuilt from the canonical envelope reproduces the digest before delivery.

## 11. Limits

- The digest proves integrity of the projection bytes against trusted expected
  inputs. It does not authenticate an origin and does not prove that the
  sources are sufficient, exhaustive or current.
- This specification describes a wire format. It defines no evaluation
  semantics, no exploitability assessment and no human risk decision; those
  three layers remain separate by design.
- Ariadne is pre-alpha. Publication of this document does not authorize
  distribution of bundles, does not claim compatibility with any external
  consumer, and does not establish support for real cluster or vendor sources.

## 12. Revisit triggers

Any change to the canonical bytes, the projection membership, the vocabulary
of §4.6 or the validation rules of §7 requires a new schema version decision
and new vectors; it can never be a silent edit of this document. If validators,
vectors and this specification disagree, that disagreement is itself a defect
to be resolved before any release.
